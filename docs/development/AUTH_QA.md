# Odbiór uwierzytelniania — #12

Gateway `/api/auth/*` wymaga aktywnego hosta `PLATFORM` albo `COMPANY_ADMIN`. Rola, firma, adres potwierdzony, stan konta/firmy i dowód MFA są sprawdzane w bazie przy każdym chronionym odczycie. Host `COMPANY_PUBLIC`, marketing, cudza firma, archiwum i cofnięta sesja są odmawiane. Koniec opłaconego okresu nie blokuje panelu. `POST` wymaga dokładnego `Origin`; cookies są host-only. Gdy brak zaufanego adaptera adresu klienta, lokalny dev używa jednego klucza `unknown`, a produkcyjny auth zwraca `503`. #13 musi dostarczyć zaufany ingress i pozytywną próbę produkcyjną; #12 jej nie zalicza.

Pierwszy superadmin powstaje przez interaktywny `pnpm exec tsx scripts/bootstrap-superadmin.ts` po migracjach na **pustej** bazie. Komenda pobiera host platformy z `BETTER_AUTH_URL` i atomowo tworzy konto, credential oraz aktywny `HostMapping`. Hasło podaje się tylko w ukrytym TTY. Drugie uruchomienie odmawia. Test `tests/isolated/bootstrap-superadmin.test.ts` wykonuje pełną drogę: pusta baza → bootstrap/host → ograniczony login → TOTP → pełna sesja. `pnpm test:integration` sam przygotowuje osobną lokalną bazę `auterva_bootstrap_12` wskazaną w `BOOTSTRAP_TEST_DATABASE_URL`; odmawia innej nazwy, zdalnego hosta i zajętej bazy. Pozostałe integracje działają na chronionej bazie fixture #9 z `DATABASE_URL`.

Po poprawnym haśle konto bez MFA otrzymuje wyłącznie sesję enrolmentu. `/two-factor/enable` wymaga tej sesji i hasła; zwraca URI TOTP bez kodów odzyskiwania. Poprawny `/two-factor/verify-totp` wymienia sesję, zapisuje jej dowód MFA i jednorazowo pokazuje 10 kodów. Późniejszy login wydaje challenge przypięty do hosta i konta; TOTP albo jeden kod odzyskania kończy go. Odpowiedzi logowania i `get-session` nie zwracają surowego tokenu. `/mfa/reauth` wymaga pełnej sesji i świeżego TOTP albo atomowo zużytego kodu; wydaje dowód dla tej sesji/konta/celu na najwyżej 5 minut. `/mfa/rotate-backup-codes` zużywa go raz, sprawdza także hasło, unieważnia pozostałe sesje i stare kody, zapisuje audyt bez sekretów. `disable`, `view`, `trustDevice`, publiczny signup i pozostałe niegotowe operacje Better Auth są zamknięte allowlistą. Reset hasła i profil należą do #18; nie są obecnie publicznymi endpointami.

Odtwórz `pnpm lint`, `pnpm typecheck`, `pnpm test:unit`, `pnpm test:integration`, `pnpm build`, a następnie `E2E_PORT=3345 E2E_DEV_PORT=3346 pnpm test:e2e` na własnych wolnych portach. E2E uruchamia równolegle oddzielny produkcyjny build PWA i lokalny serwer dev z osobnym katalogiem Next; dev nie przebudowuje produkcyjnego service workera. `auth-host.spec.ts` bada realny HTTP gateway dla aktywnego hosta, enrolment, MFA i logout. `auth-production.spec.ts` potwierdza odmowę bez ingress nawet przy starej fladze probe. W PostgreSQL integracje badają współbieżny limiter dwóch klientów, 5 niepowodzeń konta, 20 prób IP, różne sesje, jednorazowy kod/dowód, rotację, archiwizację oraz zamknięcie bezczynnego WS po cofnięciu uprawnienia. Nie publikuj wygenerowanych haseł, URI TOTP, kodów ani pliku `.env`.
